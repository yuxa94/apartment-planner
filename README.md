# 공동주택 초기 계획 편집기

59·74·84형 조닝, 동평면 후보, 단지배치의 연결을 시험하는 로컬 프로토타입입니다. 화면의 수치는 입력한 계획 가정에 대한 개략 계산이며, 인허가용 도면이나 법규 적합 판정이 아닙니다.

## 실행

`index.html`을 더블 클릭하면 브라우저에서 열립니다. 로컬 서버를 사용하려면 PowerShell에서 이 폴더의 `start-local.ps1`을 실행하고 표시된 주소를 엽니다. 화면 자체에는 외부 LLM API 키가 필요하지 않습니다.

## 세 단계

1. **단위세대**: 59·74·84형의 개략 실 구성을 살펴보고 치수·면적·잠금을 조정합니다. 참고 이미지의 실제 벡터 도면을 정밀 복원한 결과는 아닙니다.
2. **동평면**: 세대 유형과 코어를 조합해 후보를 비교합니다. 단순 배치 후보이며 실제 현관 연결·계단·승강기·피난 적합성은 미검토입니다.
3. **단지배치**: 예시 대지에서 동을 이동·회전하고 층수·잠금을 바꿉니다. 경계·중첩·거리와 개략 면적 지표를 입력 가정에 따라 다시 계산합니다.

프로젝트 JSON을 내보내 현재 상태를 보관하고, 가져오기로 복원합니다. 프로젝트 스키마는 `apartment-planner/1`, 좌표·치수 단위는 **m**, 면적 단위는 **㎡**, 개정 번호는 `revision`입니다. 이미지나 CAD의 mm 좌표를 그대로 넣지 마세요. 전체 프로젝트 JSON을 편집해 조닝 데이터를 수정할 수도 있으며, 가져올 때 형식 검증을 거칩니다.

## Astra와 파일 왕복

1. 수정할 내용을 적고 **Astra 요청 JSON**을 내보냅니다. 요청에는 `apartment-planner-request/1`, `baseRevision`, 요청문 `request`, 현재 `project`, 결과 형식 `expectedPatch`가 포함됩니다.
2. 요청 파일을 Astra 대화에 전달합니다. 이 폴더의 `skill-package/apartment-feasibility/SKILL.md`를 함께 지정하면 변경 범위와 검토 절차를 안내할 수 있습니다.
3. Astra가 만든 결과 JSON을 편집기에서 가져와 변경 내용을 확인합니다. 자동 변경 파일은 기존 동의 `x`, `y`, `rotation`, `floors`만 바꿀 수 있습니다.

```json
{
  "schema": "apartment-planner-patch/1",
  "baseRevision": 1,
  "changes": [
    {"id": "b101", "x": 55, "y": 65, "rotation": 10, "floors": 18}
  ]
}
```

예시의 개정 번호·ID·좌표를 실제 요청에 맞춰 바꿉니다. 잠긴 동, 존재하지 않는 ID, 다른 개정의 결과는 적용되지 않습니다. 요청을 보낸 뒤 프로젝트를 수정했다면 최신 상태로 요청을 다시 내보냅니다. 결과의 개정 번호만 바꿔 적용하지 마세요.

HTML은 대화나 외부 API를 직접 호출하지 않습니다. Astra 대화와 로컬 편집기를 파일로 연결합니다. 스킬은 이 폴더에 패키지로 제공되며 사용자 스킬 디렉터리에 자동 설치되지 않습니다.

## 검토 범위와 출처

`rules-reference.json`에는 2026-10-15에 확인한 공식 법령 링크와 항목별 구현 범위를 기록했습니다. `supported_screen`은 사용자 가정의 선별 계산을 지원한다는 뜻이고, `unreviewed`는 검토하지 않았다는 뜻입니다. 어느 상태도 법정 적합을 뜻하지 않습니다.

- 인동거리: 모든 면에 두 동 중 최대 높이의 같은 비율을 적용하는 보수적인 계획 가정입니다. 이것이 모든 법정 조건보다 엄격함을 보장하지 않습니다. 실제 조문은 채광면·방향·부분 높이·측벽·예외 및 지자체 조례를 구분합니다.
- 정북: 기본 비활성화입니다. 활성화하면 동의 네 꼭짓점에서 정북 방향 경계까지의 거리를 검사합니다. 벽면 전체·부분 높이·표고, 해당 대지·인접지 용도지역, 기준 경계, 예외와 조례 적용 여부는 별도로 확인해야 합니다.
- 건폐율·용적률: 단순 형상에 따른 개략 지표입니다. 법정 면적 산정과 적용 상한은 미확정입니다.
- 주차·소방 접근·피난·실제 일조: 미검토입니다. 주차 수요 추정과 거리 검사를 실제 설치·안전·일조 검증으로 사용하지 않습니다.

기본 숫자는 예시 대지의 계획 가정입니다. 지자체가 정해지면 적용 기준일·용도지역·조례·사업별 조건을 공식 원문으로 확인하고 별도 규칙으로 기록해야 합니다. 과거 참고 도면의 계수를 현재 법규로 전용하지 않습니다. [건축법 제61조](https://www.law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0061&lsiSeq=273437&urlMode=lsScJoRltInfoR), [건축법 시행령 제86조](https://www.law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0086&lsiSeq=290833&urlMode=lsScJoRltInfoR).

## 단계별 브랜치

세 단계는 각각의 브랜치에서 따로 개발합니다. 공통 계산 모듈(`engine.js`, `state.js`, `units.js`)과 데이터 계약은 공유하며, 브랜치마다 `stage.js`의 `window.PLANBY_STAGE` 값만 다릅니다.

| 브랜치 | `PLANBY_STAGE` | 화면 |
|---|---|---|
| `main` | `null` | 세 단계 모두 |
| `stage1-unit-plan` | `'units'` | 01 단위세대 계획 |
| `stage2-building-plan` | `'combinations'` | 02 동평면 조합 |
| `stage3-site-plan` | `'site'` | 03 단지 배치 검토 |

단계를 고정하면 해당 탭만 표시되고, 브라우저 자동 저장 키가 `planby-apartment-v1-<stage>`로 분리됩니다. 처음 열 때 이 키에 저장된 값이 없으면 기존 공용 키(`planby-apartment-v1`)의 프로젝트를 불러옵니다. 각 브랜치의 개발 범위는 `STAGE.md`에 있습니다.
