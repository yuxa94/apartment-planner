1. 대화로 만드는
공동주택 초기계획 도구
기존 실제 개발 기록을 따라가는 240분 강의. Git bundle로 동일 커밋의 소스를 복원하며, 만들기 실습은 시작 커밋에서 진행한다. AI가 만든 결과 커밋 해시는 강사 것과 달라도 된다. 법규는 계획 가정의 기하 검토이다.

2. 준비 + 11단계
세 단계마다 약 70분. 각 단계 앞부분은 실제 화면으로 무엇이 바뀌었는지 보고, 뒷부분에서 같은 요청을 직접 넣는다. 설치나 실행이 늦은 수강생은 강사 화면과 단계별 단일 HTML 결과물로 다음 실습에 참여한다.

3. 세 단계는 JSON 파일로 이어집니다
단위세대 평면(apartment-planner-unit/1) → 동평면 후보(apartment-planner-building/1) → 단지 프로젝트(apartment-planner/1)와 배치 변경(apartment-planner-patch/1). 단계 사이를 파일 형식으로 고정해 두었기 때문에 세 세션이 동시에 일해도 서로의 코드를 기다리지 않는다. 단위는 모두 m·㎡.

4. 오늘 만들 도구와 준비할 자료
설치와 파일 준비는 수업 전에 완료. 코드 개발은 Claude Code와 Node, CAD 읽기는 AutoCAD MCP가 필요하다. CAD 환경이 없으면 cores.json을 사용한다.

5. 첫 실습 · 단위세대 화면 살펴보기
소스와 에셋을 먼저 준비해 실제 화면부터 살핀다. Git 운영은 보조 안내 페이지에서 필요할 때만 참조한다.

6. 참고도면 치수로 다시 그린 59형
v1은 59형이 12.9×8.3m 사각형 하나에 실들이 떨어져 있었다. LH 양주회천 A-26 안내도의 표기 치수로 59A·74A·84A 외곽과 실을 다시 만들었고 세 타입 모두 빈 영역 0㎡. 외곽 면적에 발코니·벽체가 들어가 59형이 102.5㎡로 전용 59㎡보다 크다는 점을 함께 설명한다. 벽 두께·중심선은 구분하지 않은 개략값.

7. 1 · 외곽선을 정하고 꽉 차게 채우기
실제 결과: 테스트 35→42개. 심하게 왜곡한 외곽에서도 70%가 완전히 채워졌고 남은 틈의 중앙값은 0. 참고도면 겹쳐 보기에서 벽선과 0.1~0.2m 이내. 이미지 치수 판독값이므로 실측·시공 치수로 다루지 않는다.

8. 외곽선 편집 모드
조작: 변 드래그(붙은 실 함께), 변 더블클릭(직각 유지 돌출·함몰), 꼭짓점 드래그, Delete로 꼭짓점 삭제, 좌표 JSON 입력. outline 필드는 하위 호환이며 width/depth는 외곽 경계상자 크기로 유지해 Stage 2가 그대로 동작한다.

9. API 키 없이 Claude와 주고받는 방법
요청문(apartment-planner-unit-request/1)에는 현재 도면 JSON, 규칙, 영역 표시가 모두 들어간다. Claude는 patch JSON 하나를 코드 블록으로 답한다. 앱은 baseRevision이 다르거나 잠긴 실을 바꾸면 거부한다. 요청 후 화면에서 도면을 고쳤다면 요청문을 다시 복사해야 한다. 같은 구조가 Stage 3의 배치 변경(apartment-planner-patch/1)에도 쓰인다.

10. 2A · 팝업 대신 대화 패널 하나로
실제로 사용자가 “창이 새로 띄워져서 보기가 불편하다”고 해서 바뀐 기능이다. 이 단계에서 “Astra에 수정 요청” 버튼(이전 워크플로 명칭)도 지웠다. 세 브랜치가 같은 문구로 지워 병합 충돌을 피했다.

11. 2B · 빨간 영역으로 위치를 가리키기
공통 검증 모듈(state.js)을 고치지 않으려고 빈 도면도 59/74/84 중 기준 평형을 고르게 했다. 편집기는 이때부터 평형이 아니라 도면 id(selectedUnitId)로 도면을 고른다. Stage 2와 합칠 때 확인할 지점이다.

12. “A 자리에”와 “A 쪽으로”는 다릅니다
요청: “영역 A 쪽으로 현관 이동시켜주고, 거실이랑 복도는 합쳐줘.” 사용자 피드백: “A 자리에 그대로 넣으란 게 아니라 A 쪽으로 현관을 옮기면서 내부 배치도 새로 하라는 뜻이야.” 이런 해석 차이를 모델 지침에 남겨 두면 다음 대화에서 반복되지 않는다.

13. 레이어 패널과 Claude 대화 패널
면적표를 레이어 패널로 바꿨다. 드래그 또는 ▲▼로 순서를 바꾸고, 완전히 가려진 실만 경고한다. 선택한 실은 가려져도 점선으로 전체 범위를 보여 준다.

14. 3A · 실 크기 조절과 레이어
레이어 규칙으로 바꾸면서 기존 “겹침 금지” 테스트 2개를 새 규칙에 맞게 고쳤다. 테스트 44→45개. 데이터 의미를 바꾸는 요청은 테스트도 같이 바뀌어야 한다는 예로 쓴다.

15. 겹침은 오류가 아니라 레이어입니다
Claude에게도 같은 규칙을 지침으로 준다: 배열 뒤쪽이 위 레이어, 직사각형이 아닌 공간은 큰 사각형을 아래에 두고 다른 실로 덮어 만든다.

16. 3B · 가까운 변과 꼭짓점에 스냅
실제 기록: 침실 2의 왼쪽 변이 7.34→7.40 선에, 공용욕실이 10.26→10.15 선에 붙었다. 수정 후 Ctrl+Z로 원래대로 돌리고 커밋했다. 테스트 49개.

17. 10분 쉬어갑니다
강사는 Stage 1이 막힌 수강생에게 package/planby-unit-planner.html을 열게 한다. 80분에 수색4 도면 화면으로 돌아온다.

18. 수색4 101동 A-303 · 복도형 4세대 + 후면 코어
사용자 첫 피드백: “지금 GPT가 만들어 놓은 배치 조합이 너무 별로여서 참고자료랑 대조하면서 보자.” v1 생성기는 세대 방향·현관 정보가 없고 임의 패턴 3종이었다. 101동과 106동(A-375)을 옆에 열고 문제를 표로 정리한 뒤 101동 재현부터 시작했다.

19. 4 · 참고 동평면을 그대로 재현하기
중간에 어시스턴트가 “LH 세대 방향이 90° 틀렸다”고 했다가 스스로 정정했다. LH 59A는 전면 12.9m의 4베이라 현재 방향이 맞다. 그럴듯한 설명도 도면과 대조해 확인해야 한다는 사례로 쓴다.

20. 재현 결과 · 도면과 생성값
커밋 0cbd2e1. 이 뒤 “더 여러 조합으로”라는 요청에 편복도 조합 75안을 만들었지만, 사용자가 의도와 다르다고 해서 커밋 전에 되돌렸다. 화면을 먼저 보고 커밋하는 습관이 이런 경우를 막는다.

21. 코어 1개에 세대를 붙이는 경우의 수
사용자가 면적표 이미지를 첨부하며 “코어 1개에 유닛을 붙일 수 있는 경우의 수를 탐색하는 거였어”라고 방향을 바로잡았다. Stage 1의 unit-59/74/84.json을 받아 실제 외곽과 현관 위치로 조합한다. 외곽 면적이 Stage 1과 정확히 같다(102.54 / 120.65 / 140.651㎡).

22. 5A · 코어 1개 + 세대 경우의 수
첫 결과 4세대 21안, 3세대 54안, 2세대 51안(가정 홈 치수). JSON 연동 후 4세대 11안, 3세대 53안, 2세대 48안. 세대 외곽 해석 차이(84형 14.9×10.57 대 13.8×9.4)는 공유 노트로 Stage 1에 알렸다.

23. 5B · 층수에 따라 코어를 부품으로 조립
25층 기준 4세대 15인승 2대, 3세대 13인승 2대, 2세대 15인승 1대. 31m 초과 시 비상용승강기. 모두 선별 계산이며 법규 적합 판정이 아니다. 커밋 7a54467(탐색), ea29484(부품화).

24. 6A · AutoCAD MCP로 실제 코어 DWG 읽기
실제 기록: 사용자가 “로드완료”, “core-59A.dwg 탭을 활성화하고 mcp_dispatch.lsp를 다시 로드했어”라고 두 번 알려 줬다. 결과 59A 6.0×8.2m, 84A 7.5×7.9m, 53A 9.6×9.7m, 101/103/104동 15~19×14~15m 타워형. 59A·84A에서 계단실과 샤프트가 0.25m 겹친 판독 실수를 테스트가 잡았다. 추출 기록은 tmp/core-extract-20261015/.

25. 코어 먼저 → 세대 먼저
사용자 요청: “테트리스 할 때 쓰는 로직처럼 실들을 붙여서 배치하고 그 사이에 코어를 넣는 형식으로.” 세대를 벽끼리 2m 이상 맞붙이고, 거실 앞 6m 안에 다른 세대가 들어오면 버린다. 현관 앞 1.5m를 비우고 폭 1.8m 복도 띠로 현관을 잇는다. 이후 화면 문구에서 “테트리스”는 지웠다.

26. 6B · 세대 먼저 맞붙이고 빈틈에 코어
개선 후 2세대 129안(공용 40/49㎡), 3세대 135안(53/56㎡), 4세대 21안(70/72㎡). 계산 약 3초, 같은 조건이면 캐시. 남은 문제: 일부 조합에서 계단이 건물 밖으로 튀어나온다. 커밋 217e190, 54b3670.

27. 저장한 안 편집 탭
요청 순서: 향 필터 3분리와 창 방향 표시 → 저장한 안 편집 탭 → 코어 부품 바운딩박스 크기·회전 → “90도 회전만 된다, 자유롭게” → Stage 1의 스냅·외곽 push/pull 이식 → 문·창 이동·삭제. “회전이 안 된다”는 피드백은 데이터는 돌았지만 정사각형 승강기가 화면상 같아 보였던 것이라, 승강기 문과 계단 화살표를 그려 해결했다.

28. 7 · 후보를 JSON으로 저장하고 손으로 고치기
면적·창·향은 가져올 때 형상에서 다시 계산하므로 형상만 고쳐 넣으면 된다. 84형 JSON의 안방이 원래 외곽 밖으로 조금 나와 있어 생긴 오탐은 “편집 시작 때보다 더 나간 경우만 표시”로 고쳤다. 테스트 62→63개.

29. 두 번째 휴식 · 10분
Stage 2 후보 JSON 하나를 저장해 두게 한다(10A 실습에서 사용). 160분에 인동거리 비교표로 돌아온다.

30. 단순 0.5H가 틀린 두 경우
사용자 요청: “실제 동배치도 레퍼런스를 보면 인동거리나 일조사선 검토를 하고 있는데 레퍼런스처럼 할 수 있어야 해. API 키 없이 너랑 대화하면서 어느 정도까지 되는지 검토하고 싶어.” 코드를 바꾸기 전에 대화만으로 101-103동을 계산해 앱 판정이 반대로 나온다는 것을 먼저 보였다. 수치는 예시 대지·사용자 가정 기준.

31. 창이 있는 면과 측벽을 나눠 봅니다
청주시 조례 프리셋 기준 예: 채광면↔채광면 1.0H, 남측 저층은 10m 이상이며 낮은 동 1.0H, 측벽↔측벽 4m. Stage 2에서 가져온 동은 실제 창이 놓인 면을 채광면으로, 창이 없는 면을 측벽으로 판정한다.

32. 8 · 계약안을 먼저 받고 구현하기
첫 요청 “거리선 라벨에 실제/요구값을 같이 보여주고 미충족이면 빨갛게”가 26022ec. 계약 문서는 공유 메모 폴더에 남겨 Stage 1·2가 병합에 대비하게 했다. 테스트 35→45개, 커밋 0136f32.

33. 높이 H는 산식으로 정합니다
AG-109: 1층 3.5 + (층수−3)×기준층고 + 3.0 + 3.0 + 파라펫 0.4. 1층 전체 필로티 동은 1층을 높이에서 뺀다. 도면 표의 15층 값(43,500 / 43,300 / 40,000 / 39,800)과 20·29층 값을 맞췄다. 삼송 산식은 0.6 + 층수×2.8 + 0.25(15층 42.85m). 높이가 바뀌면 정북 이격 요구값도 함께 바뀐다.

34. 인동거리배치도 형식의 도면 보기
사용자가 실제 인동거리배치도 스크린샷을 첨부하며 “이런 식으로 볼 수 있으면 좋겠다, 스크린샷의 법령 기준을 추가하고 더 추가할 게 있으면 찾아서 추가해줘”라고 요청했다. 가능 영역은 법정 연속 허용 영역이 아니라 1~5m 간격으로 검사한 위치다.

35. 9A · 법령 프리셋과 도면 보기
청주시 조례 제35조 정북 기준 높이는 2023-12-22에 9m→10m로 바뀌었다. 첨부 도면(2023.08)은 개정 전이다. 과거 도면의 계수를 현재 기준으로 그대로 쓰지 않는다는 원칙의 실제 예. 커밋 be4b1a6, 테스트 58개.

36. 작업 당시 프리셋 · 적용 전 원문 확인
“supported_screen”은 선별 계산을 지원한다는 뜻이지 법규 통과가 아니다. 판정은 입력한 기준 프리셋에 따른 기하 검토라고 매번 밝힌다.

37. 외부 라이브러리 없는 3D 매스
SVG 축측 투영으로 만들어 오프라인 단일 파일 원칙을 지켰다. “회전할 때 줌이 바뀐다”는 피드백의 원인은 보이는 건물 크기로 뷰 범위를 매번 다시 잡은 것이었고, 대지와 최고 동 기준 고정 범위로 고쳤다. “좌우가 반대”라는 피드백은 한 줄 수정(eff3a32).

38. 10A · Stage 2 동평면을 대지로 가져오기
예시 파일의 동 외곽은 20각형 401.95㎡, 파일의 footprintArea 635.97㎡는 외접 사각형이라 쓰지 않았다. 회귀 테스트용으로 fixtures/building-3u-59x2-74x1.json을 남겼다. 커밋 2f446b7, 테스트 67개. 동 회전 핸들 b98cc61, 대지 경계 편집 4f03d8c는 별도 커밋이며, 2f446b7의 동평면 가져오기에 앞선 기능이다.

39. 10B · 조건을 충족하는 배치안 만들기
